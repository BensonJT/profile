How I evaluate AI

Evaluation

Deterministic code does the bulk of the work, and a model is trusted only where it has been measured. One evaluation story per project, in date order.

AI evaluation · As of October 20, 2026

Deterministic by default.

I build AI systems that depend on AI as little as possible. If a step can be deterministic code, it is. A model gets a step only when reading or writing language is the actual task, and only after it passes a bar I wrote down before the test. Then code checks everything it returns.

Share of each system’s code that calls a language model:

Meridian

2–4%

All of it reads the news. Everything with a number in it is code, and the overnight batch calls no model.

Forester

0%

AI built it; none runs in it. 0 of 470 modules call a model.

Requirements Fit Analyzer

10%

Two of the eleven nightly stages call a language model, both near the end. 19% counting the local embedding models.

AdoptiScope

0%

No AI at runtime, by design: the diagnosis stays with the practitioner.

Sheets Decomposer

0%

Code finds the defects. A model only explains them, and it sees the structure, never the data.

Benson Academy

4%

All of it calls Gemini’s text-to-speech model to read the lessons aloud. No module writes text with a model, and the local Whisper code that checks the audio is mostly checking, not making.

Measured October 27, 2026, from the tracked source code, with tests and generated code left out; a module counts if it makes the model call. Across all six, 10 of 973 modules call a language model, and the three in Benson Academy only make audio.

That choice pays off four ways. Deterministic stages cost nothing per run. A model outage stops one step, never the run. The same input gives the same answer, so the code gets pass-or-fail tests. And private data stays local, with the model sent the least it needs. What’s left for AI is small enough to evaluate properly.

Benson Academy · In production

Turn AI-made media back into text, then judge it with code.

Every Abide lesson is read aloud by Gemini’s text-to-speech model, a large language model that turns a script into speech, and the same model voices the podcast. No text checker can read audio, so a free Whisper model on my own machine transcribes each section that comes back, and code compares that transcript with the script we sent. The script is the golden source, and the size of a miss decides what happens. A large miss, like an invented sentence, a dropped passage or a sentence read three times, means the audio is wrong, and that section is requested again. A narrow miss gets investigated, because the transcription itself can be slightly wrong: I listen to that spot against the script. Before a lesson is done, I listen to the whole thing, reading along.

How it is checked ↓
  1. Send the approved script to Gemini’s text-to-speech model, 100 words at a time
  2. A pace check rejects any piece read too fast or too slow
  3. Whisper transcribes the audio that comes back, on my machine
  4. Code compares the transcript with the script we sent
  5. A large miss is requested again; a narrow miss, I check by ear
  6. I listen to the whole lesson, reading along, before it’s done

May to July 2026 · Forester

A claim about a model is a test, not an argument.

Forester has no AI inside it yet, but it will have an interview agent, so I argued about how that agent would read field names. Then I tested it: 12 blind Claude Sonnet runs in a 2 × 2 × 3 design. Given a field named _pct and no stated scale, Claude wrote 15 for 15% in 3 of 3 trials, a hundred times too large. Named _rate, it wrote 0.15 every time, and with the scale written down both names worked. I recorded the result even though it corrected half my argument, and it changed the build: a generated field reference for the future agent, behind a drift gate.

The other lesson was about checkers. Test cases generated by the engine had locked in the engine’s own bugs, so the lists that check Forester’s Coach are now written by hand.

Carried forward: run the experiment, and write down the expected answer before the engine runs.

August 2026 · Meridian

The bar comes before the run.

Meridian was the first time a language model wrote to a production database, reading news for sentiment and dated events. I didn’t pick the model by argument. Four candidates ran on the same 120 frozen articles, scored against answers set by two Claude raters, with Claude Opus settling the 24 rows where they split. I wrote the bars before any run: 85% sentiment agreement overall and 90% on articles that aren’t neutral. Then I graded the graders. Against the settled answers, Claude Haiku, one of the two raters, scored 83.3%, below the bar. I kept the bar. Gemma 4 31B cleared it at 93.3% and 97.9%. One prompt revision was adopted on its numbers and the next was rejected on its numbers.

In production, every row the model writes records the model and prompt version, every quoted date must appear word for word in the article, and a known fact always overrides an inferred one.

Carried forward: write the bar first, measure the measurer, and record where every answer came from.

September 2026 · Sheets Decomposer

Even the answer key was wrong.

Sheets Decomposer’s code finds a spreadsheet’s defects, and a model only explains them. The model sees the structure and never the data, so an invented value is easy to spot. To test it, Claude built a practice workbook with 15 planted defects and an answer key, and a 24-question test with four trap questions. On the first run, Gemini corrected the answer key: one defect sat in a different month and row than the key said. It also found a defect nobody had planted. On October 20 I re-ran the test with Claude Sonnet standing in. It scored 24 of 24, found the key wrong again, and found that three labels in the sample were giving the answers away. I neutralized the labels, kept the new defect in the key, and re-ran: 24 of 24.

Carried forward: when a model disagrees with the key, check the key, and the test data too.

September 2026 · Requirements Fit Analyzer

A judge keeps only the role it passed.

The Requirements Fit Analyzer uses five kinds of machine judgment, and every one is scored against the same ground truth: my own fit grades, counting only the ones I gave before I saw any machine score. Each has a written bar, and a model that fails keeps only the role it earned. Embeddings failed as a ranker, at 0.669 against the trained models’ 0.955, and now explain rankings instead. A Gemma second judge never passed in eight rounds and now appears only as evidence. Jev passed the Required-fit bar, catching 91% and agreeing 93%, but failed calibration, so the Required call is the only thing it acts on. Since October 20 it hands grey cases to me instead of demoting them.

I measured myself too. Between my first pass on one blind sheet and my final grades, 55 of 72 grades stayed the same. A judge that’s a person is still a gauge.

Claims are selected, not written. When I started, AI drafted tailored documents from a long skill and a full biography, and too often it mixed metrics from different projects into one new claim. I moved the facts into a database: 202 statements, each re-audited against my records and my memory, and tagged with its project, the problem it solved, the section it belongs to and what it must never be used to claim. For each requirement document, AI selects the 14 to 16 that fit and uses them word for word, with their context lines, and a script builds the Word file. Tests keep the verbs varied within each context and section: the 202 statements open with 140 different verbs. AI still drafts the summary and picks the skills, under strict rules, and I review every document before it goes out, usually adjusting those two parts and sometimes asking for another statement. Slight edits to two paragraphs beat a whole document that drifts.

Carried forward: grade the graders as a measurement system, me included, and where the facts matter, select instead of generate.

September 2026 · AdoptiScope

Sometimes the right amount of AI is none.

AdoptiScope turns a practitioner’s scores into a barrier reading, and no model makes that call: a tool that takes scores and hands out interventions would be the prescription engine my articles argue against. AI built it, though. Claude Code wrote the generator and drafted the method content from my six articles, so the checks aim at what AI made. The rules are written twice, as spreadsheet formulas and as Python. A hand-built answer key must agree with the Python, and real Excel and real Google Sheets must agree with the key: 134 of 134 values in each. Every practice the AI drafted cites the article it came from, and an earlier AI-written summary with broken citations is banned as a source by name. Since October 20, lint and all 25 tests run before every commit.

Carried forward: trace every AI-drafted word or formula to its source.

October 2026 · Keystone

A peer researcher, trained in the method.

Keystone is where I keep the standard work my AI tools follow, and one thing it does is turn an expert’s written method into skills, so Claude works as a peer researcher, the way it’s already a peer in programming. My worked example is the Bible study method behind the Abide course. On October 4 I wrote it from the course’s own textbook into Claude skills: a router and eleven step files, about 15,000 words, backed by scripts that pull the source text instead of quoting from memory. I gave it two public-domain translations as local files, with their word tables, so Claude can find the original-language word behind an English one, find the other passages that use the same word, and point them out to me. Then we read the lexicons together to settle what the word means. Licensed translations come live from their publishers. The same approach fits any discipline with a written method: audit standards, clinical guidelines, a company’s playbooks.

The skills teach it to be the research partner I’d want. It pulls every passage with a tool, treats its own cross-references as leads to check rather than proofs, claims what a word means only from a lexicon I’ve pasted, and lays out a contested reading with who holds each view, leaving the call to me. Then I pointed those skills at my own course. Working the method the textbook teaches, Claude found errors I had made: a word study that drew a word’s meaning from its English derivative, the very fallacy the textbook warns against, and a passage labeled as one translation that carried another’s wording. I ruled on every finding, and the rulings became written rules every lesson is audited against. Abide’s quote checks run on the same source-text scripts.

Carried forward: the skills that make AI a good research partner also make it a good auditor, of my work as much as its own.

October 2026 · Benson Academy

Everything I’d learned, applied to audio and source texts.

The audio check in the feature above uses all of it. The bars are written in code: spelling-only differences are noise, and a second, larger Whisper model re-audits every finished file, flagging any match under 97% or any run of more than three words skipped or added. The transcriber is treated as a gauge that can be wrong: a podcast part fails only if both Whisper models fail it, and where they disagree, I listen. Claude wrote the scripts that run it overnight, requesting the audio, transcribing and scoring with no Claude tokens spent running or watching them, and a flagged file holds the queue until it’s fixed. The checks have caught about 42 seconds of invented speech, a dropped passage, a misread name, and a sentence read three times while the generator reported success.

Text gets the same treatment, using Keystone’s source-text scripts. Every quotation of the course’s primary text is checked by script against a public-domain ground-truth file, and must sit in the passage it cites. Every quotation of a scholar must match a paste from my library, filed by script byte for byte, under the citation of the source the lesson credits. On October 20: 200 source passages and 862 quotations across the five lessons in the current release, with 0 differences. I approve every section, theology and tone are mine, and no lesson is done until I’ve listened to all of it, reading along.

Since October 20 the checks are gated in both places the content lives: the app blocks a commit whose lesson content fails and a push whose build or tests fail, and the vault’s validation run logs every pass. The first push the new gate guarded was blocked by six regressions.

Green isn’t the evaluation.

Most of this code was written by AI, so the code is checked as hard as the models are, at every step from commit to deploy.

At every commit

Meridian and Forester run lint, formatting and fast tests or type checks before any commit; a failure means no commit. AdoptiScope runs lint and its 25 tests. Abide’s app blocks a commit whose lesson content fails its source-text and quote checks.

At push and deploy

Forester runs GitHub Actions on every code push: migrations, lint, type checks, the full test suites, then Playwright end-to-end tests; Vercel builds the deploy, and a failed build never replaces the live site. Abide’s app runs its build and Playwright suite before any push. Meridian’s deploy is a ledger of database migrations, checked by checksum on a machine I never touch.

Inside the build loop

The autonomous build loops can’t mark a task done until its gates pass, three failures mark it blocked, and every stage ends with a stop for my sign-off. Forester’s rules engines are written twice, in TypeScript and Python, and must agree byte for byte on about 890 fixture cases.

After the loop

A passing suite the loop wrote itself is not the acceptance test. An independent audit of one Meridian stage found 9 defects, 3 of them high. When I mutation-tested the loop’s own tests, 4 of 13 planted defects got through; after the fixes, 15 of 15 were caught.

Always improving. Evaluation here keeps changing. On October 20 alone, AdoptiScope gained a pre-commit gate; Abide’s checks were gated in both places its content lives, its quote checker began tying each quote to its cited verse and credited source, research pastes are now filed by script, and licensed translations are checked live with a stored copy as backup, so a verse the publisher revises is flagged for me rather than silently changed; Jev began handing grey cases to me; and a model caught Sheets Decomposer’s test data giving answers away, so it was fixed. Next: a scheduled drift check for Meridian’s news model, and decoy documents in the Requirements Fit Analyzer’s blind grading sheets to measure Jev’s demotions directly.

As of October 20, 2026; counts are approximate and will grow. AI helped build all of it: Claude for most, Gemini for some, and I pushed some commits myself.
