Context: Load Only What the Step Needs

Routers, Skills and Notes: How My Agents Read 1% to 5% of Their Instructions

Jeffrey Benson  ·  2026

Deterministic First: Agentic Systems  ·  Part 1  |  Part 2  |  Part 3

In October I tested a voice guide: a file describing how my sentences sound, written so an AI could draft in my voice. I graded the drafts blind. In the first round, both drafts written with the guide scored 2 or 3 out of 5. The draft I rated 5 had no guide at all and reused my own wording from my notes. Both guide drafts also used the word "plainly," which I don't use. It came from the guide itself, where it described how I write.

In the second round, the guide plus my own words scored 5 and 5, the guide alone 4 and 4, and no guide 3 and 3. The lesson I took from those two rounds: what we put in front of a model shows up in what it writes. Loading instructions is a design decision, and more is not automatically better.

This article will not cover how language models work inside. Rather, we will look at how my agents decide what to read: a short file loaded every time, a map, one router per role, and reference files loaded one step at a time. Part 1 covered workflows and Part 2 covered agents and their tools. This part covers the other half of Part 2's subtitle, the engineered context.

Vocabulary

Context is a budget

Anthropic defines the term this way: "Context engineering refers to the set of strategies for curating and maintaining the optimal set of tokens" during a model's work (Rajasekaran et al. 2025). The context is everything the model has in front of it at that moment: instructions, files it has read, tool results and the conversation so far.

Why not load everything? The same article describes context rot: "as the number of tokens in the context window increases, the model's ability to accurately recall information from that context decreases." It concludes that context "must be treated as a finite resource with diminishing marginal returns," and that models have an "attention budget" that every new token draws on. Its guiding principle is "finding the smallest possible set of high-signal tokens that maximize the likelihood of some desired outcome."

My instruction files hold 242,670 words in 147 files (as of November 12, 2026). No step needs most of them, and my voice-guide test showed that the ones a step doesn't need can still change the result.

The layers

From a short file to one reference file

Anthropic's Agent Skills article describes three levels of progressive disclosure. First, "the agent pre-loads the name and description of every installed skill into its system prompt." Second, when a skill fits the task, the agent reads that skill's main file. Third, the skill's linked files, "which Claude can choose to navigate and discover only as needed" (Zhang, Lazuka and Murag 2025). My setup follows the same idea, with a map added between the first and second levels:

Anthropic's article notes that Claude Code works this way by design: "CLAUDE.md files are naively dropped into context up front, while primitives like glob and grep allow it to navigate its environment and retrieve files just-in-time." That is why my CLAUDE.md is short. Everything in it is paid for in every session.

How does the agent know when to load a file? 123 of the 147 files open with a short "AI usage" header saying when to load it, what it covers and what to load beside it. The map repeats the "load when" part in one line, so the agent can choose without opening the file.

The measure

How much of the instructions one step reads

1. The question it answers. At a given step, what share of all my written instructions does the agent load?

2. What goes in. The word count of every instruction file, and the list of files that one step loads.

3. What it does. It adds up the words in the files the step loads and divides by the words in all the files. Let's work one: retaking a narration section for an Abide lesson loads CLAUDE.md (253 words), the map (1,405), the Abide Production router (4,209) and the narration file (3,420). That is 9,287 words, and 9,287 ÷ 242,670 = 3.8%.

4. How to read it. A low share means the step's context is mostly about that step. It is a rough measure: it counts words, not tokens, and it leaves out the files and tool results the agent reads while it works.

5. Where it is used. Here are four steps from my own work:

Each step loads between 1% and 5% of the instructions. The memory index and the skill descriptions add about 2,400 words to every session on top of these.

The exception

The Backlog, and the agent we're designing next

One file breaks the pattern. My Backlog, the running list of open items across every project, is read at the start of every session, and it has grown to 20,459 words: 8.4% of the instructions by itself, more than any one step's instructions. Anthropic calls this kind of file structured note-taking: "the agent regularly writes notes persisted to memory outside of the context window," and those notes "get pulled back into the context window at later times." The pattern works. The file has grown too long to read in full at every start.

We are already designing the fix as the first build of a new agent, a Personal Assistant for email, calendars, chores and to-dos. The design moves the Backlog into a database: a command and agent tools open, update and close items, and the agent reads only the items for the task at hand. After each change, the Backlog file is rebuilt from the database as a read-only view, so tools without database access can still read it.

That design comes from an agent I already run. My job tracker moved into a PostgreSQL database on October 21. A command-line tool writes every change and rebuilds a read-only tracker page after each one. Six days later I added a small desktop applet on top of the same database, so I can update a job's status, add notes and attach a contact without typing a command or asking an agent to do it. The agent uses the command, and I use the applet. The Personal Assistant will follow the same path: the command and agent tools first, then an applet for me on top of them. It will also start from the routers, skills and checks that Job Search and Abide Production taught me. It is at the design stage, nothing is built yet, and I will measure it the same way once it is.

Deterministic first, again

Scripts that check the instructions

The instructions get the same treatment as the work in Parts 1 and 2: a script checks what has one right answer.

  • skill_audit.py checks every skill file: the "AI usage" header near the top, a length limit (a warning over 300 lines, a failure over 500, which means split it into reference files) and a contents list on any file over 100 lines. On November 12: 99 files passed, 4 had warnings, none failed.
  • voice_check.py counts the habits that aren't mine in any draft in my voice, including the words a guide can leak into a draft.
  • A weekly memory audit proposes which notes in the agent's memory should move into the vault's skills and lessons-learned files, where the right router loads them on demand. Durable facts were moved out of memory in two passes, on October 2 and October 19.

Continuous improvement

Skills are fixed while they are used

My rule for the agents is to finish the task, then propose the small fix to the skill that would have made it easier. Between October 24 and November 12, 2026, that produced 128 deliberate commits to skills, voice guides and lessons-learned files (not counting the automatic syncs).

Here is one from the day I wrote this. The Abide article skill told the agent to check Scripture by script and then have me check every quotation by hand in Logos Bible Software. The checkers and the tools that pull Scripture from its sources (Part 2) now do that work, so the skill now says: the checkers confirm every quotation, the tools fix any difference, and Logos is used only for a translation no tool covers. A rule that changed in how we work changed in the instructions the same day.

Each agent I build starts from what the last one taught. Job Search taught gates and measurement. Abide Production taught scripts in the evaluator's seat. Both taught routers and one-step-at-a-time loading. The Personal Assistant starts with all three.

Glossary

Terms used in this article

Context
Everything a model has in front of it at one moment: instructions, files, tool results and the conversation.
Context engineering
Choosing and maintaining what goes into the context at each step.
Context rot
A model's falling ability to recall information as its context grows.
Attention budget
Anthropic's term for the limited attention a model spreads across its context.
Token
A short piece of text, often part of a word. Context size is counted in tokens.
Progressive disclosure
Loading detail in levels: a description first, the main file when it fits the task, linked files only when needed.
Router
One role's main skill file: its rules and the list of its reference files.
Reference file
One step's procedure, loaded when the agent reaches that step.
Structured note-taking
An agent writing notes outside its context and reading them back later.
Read-only view
A file rebuilt from a database after each change, for reading only.
