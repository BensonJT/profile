How AdoptiScope is built

AdoptiScope is built as code. Nobody edits the workbook by hand: a change goes into the code or the method content, and a rebuild produces the new Excel workbook and the new Google Sheet, verifies both, and refreshes this guide.

One source of truth

The workbook is generated, never edited.

Spreadsheet templates drift. Someone fixes a formula in one copy, adds a column to another, and a year later nobody knows which version is right. AdoptiScope has one source of truth: the method's words live in content/library.yaml, the workbook's layout and formulas live in Python, and both targets are generated from them. Excel and Google Sheets can't disagree, because neither is edited.

Every build is checked the same way. Excel itself opens the file, recalculates it, and must report no errors and no circular references; Google Sheets computes its own copy, read back through its API. For the worked example, both are compared against an answer key: the barrier, flag and check every population should produce.

The code was written with Claude Code, Anthropic's agentic AI coding partner, working from the design and the method articles, with Jeff reviewing. The same partnership keeps it current: describe the change, Claude Code makes it in the generator, rebuilds, and verifies.

Run it

From a terminal on the laptop.

Everything runs from the ~/first folder through the ./first command.

cd ~/first
./first doctor                                   # is everything ready? lists the last builds
./first auth                                     # Google sign-in (weekly while the app is in testing)
./first build --example meridian --target both   # build + verify Excel and Google Sheets
./first build --target both                      # the blank template
./first build --release                          # copy the verified .xlsx into releases/
./first docs --shots                             # regenerate this guide and its screenshots
./first publish-docs                             # copy the guide into ~/code/profile/first

Changing AdoptiScope

The change cycle.

  1. Describe the change (a new column, a reworded signal, a new view).
  2. Change the code or content/library.yaml, never the workbook.
  3. ./first build --example meridian --target both: builds both, verifies both, checks the answer key.
  4. ./first docs --shots: regenerates this guide and its screenshots.
  5. Review the guide's prose with an AI pass where the change affects what a page says.
  6. ./first publish-docs, then commit and push the profile site.

Every build is verified the same way on both platforms: the file must open without repair and recalculate with no error values, Excel must find no circular references, and for the worked example 134 computed values must match its answer key, in real Excel and in Google Sheets.
