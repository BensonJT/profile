Requirements Fit Analyzer · Process map

How the Requirements Fit Analyzer works.

A system that reads requirement documents and measures how well each one fits a verified record of my work. Its first job is my own career search. Every night it finds open roles and judges each one against my record. I decide where to apply, AI selects verified statements for each application, and every call and every edit I make flows back into the next night and the next draft.

The map

Seven phases in one loop.

Scripts do everything that has one right answer. AI reads and writes only where the words matter, and only after passing a bar I wrote down first. I make the calls and supply the ground truth. Select a phase to open its detail; each number matches a note below the map.

How to read this map

  • Script. Code that gives the same answer every time.
  • AI judgment. A model reading or writing language.
  • Me. The calls only I can make, and the ground truth.
  • Gate. A check the work must pass to move on.
  • Note. Explained in the numbered list below the figure.
  • Feedback. Results flowing back to improve an earlier phase.
  1. Find. Every night a script pulls each employer’s own job board and fetches the full text of every new posting. I choose which employers are on the list.
  2. Judge. Rules, trained models and a small embedding model score each posting. Two AI judges read the Required block of the shortlist.
  3. Validate. Every judge is scored against my own blind grades and keeps only the role its score earned.
  4. Decide. I make the calls: build, pass or hold. Grades I give before seeing any machine score become the answer key the judges are scored on.
  5. Build. AI selects verified statements, word for word, from a database of my work and drafts the letter. Scripts check every fact and phrase, then build the Word files. I edit and send.
  6. Learn. My calls retrain the models through a gate. A script finds every edit I make to a sent document and AI explains why, so the voice guide and the record of my work both improve.
  7. Publish. A snapshot of each night rebuilds the reports, charts and presentation. I review anything new before it goes public.

The guardrail ring. The scripted checks every phase passes through: the gate a retrained model must clear, each judge’s accuracy bar, the repeatability bars an AI judge passes before it may act, the guards on every statement, the check on opening verbs, and the check on every finished document.

Detail 1 of 5 · Phases 1, 2 and 7

The nightly run.

One run finds every open role, scores it, and rebuilds the reports before I look at them. Scripts run it from start to finish, and the two AI steps come near the end and read only the shortlist.

  1. Wake on schedule. I pick the start time. A scheduled task wakes the laptop five minutes before it, so a sleeping machine still runs, and the pre-flight checks run twice: when I confirm and when it starts.
  2. Apply my calls. The build, pass and hold calls and the grades I entered during the day wait in a queue. They are applied first, so tonight’s scores already know them.
  3. Retrain the models. When a retrain is due, the fit models train again on my latest calls and grades. A new model replaces the old one only if it clears the gate: a shuffled-label check for leaks, accuracy no worse than the last model that passed, and no drop in labels. A model that fails is discarded, and every attempt is logged.
  4. Pull every job board. A script pulls each employer’s own job board, the same data its careers page shows. New postings are added and returning ones reopened. A posting is closed only when a clean, complete pull no longer lists it, and nothing is deleted, so every posting keeps its full history.
  5. Fetch the posting text. The full text of each new posting is fetched, along with a share of the older ones still missing it. A posting fetched again keeps the grade it already has.
  6. Screen by rules. Rules screen each posting on function, level, location, clearance and discipline. Every verdict keeps its reasons, so when a rule changes, the postings it screened out can be reopened.
  7. Score with trained models. Small trained models score fit on my three lenses: process, technical and applied AI. The best of the three sets the rank. Two more score the Required block and the closest matches, and their scores are shown beside the rank.
  8. Match requirements to my record. A small embedding model that runs on the laptop matches each requirement in the posting to the piece of my record that answers it, and marks it strong, partial or a gap. As a ranker it scored 0.669 against the trained models’ 0.955, so its job is to explain the rank.
  9. AI review of the shortlist. Jev, TypeSafe AI’s model for fast typed decisions, reads the Required block of each posting on the shortlist. A clear fail is demoted. A fail that rests only on grey lines comes to me to check. A posting I have already ruled on is never judged again: my call outranks Jev’s.
  10. Second read of the demotions. Gemma, a second AI judge, reads only Jev’s demotions. It never passed its accuracy bar in eight rounds, so its read is shown as evidence beside each demotion and decides nothing.
  11. Apply my calls again. Calls I made while the run was going are applied before the snapshot, so nothing I decided waits a day.
  12. Snapshot the night. One snapshot copies the night’s results into the reporting database in a single swap, so a report never reads a half-finished night.
  13. Rebuild reports and charts. Forty-five seconds later the reports, charts, workbook and presentation rebuild from the snapshot, and my application tracker refreshes. If nothing changed, nothing rebuilds. The public charts show only industries and percentages.

Why a script here, and judgment there.

Pulling boards, screening, training and scoring models, and rebuilding reports each have one right answer, so code does them the same way every night. AI reads only where the words matter: the Required block of a shortlisted posting, after the trained models have ranked it. Two of the eleven nightly stages call a language model, both near the end.

What I do: pick when the run starts, choose the employers on the list, and make my calls in the app during the day. The grey cases wait for me when the run finishes.

On scoring nights the run also scores the AI judges against my blind grades. That part is in Judges and validation.
